# Native Chotu popup follow-up

Analysis found two concurrent database initialization paths and a dark host
theme inherited by the light popup. The assistant also started POS sound,
notification and FCM initialization unnecessarily. The panel blur was expensive
and cannot usefully blur a different Android application's surface.

The activity now draws a native startup card until Flutter displays its first
frame. The visible Flutter popup owns one preparation future, restores Firebase
and the local session, then checks server access before microphone startup.
Failures keep input gated and expose Retry. Main POS initialization is unchanged.
The popup uses an explicit light theme, darker text, a 96% white surface and a
repaint boundary instead of blur. No checkout, order, payment or entitlement
logic was changed.

Validation: Android ARM64 profile build completed in 198.7s / 91.5 MB and was
installed successfully on the connected phone. Native ASSIST launch reported
2793ms COLD initial-window TotalTime, versus one pre-change 4694ms WARM launch.
These are single observations with different process states, not a controlled
benchmark or backend/microphone-ready timing. The phone screenshot was inspected:
title, table/language, message, microphone and input are readable over the
underlying app. The microphone reached its no-speech state; no order/payment was
submitted. Three-file Flutter analysis found no issues.

Logs/APK and private screenshots are in build/chotu_popup_validation/.
The final combined run passes 34 checks in clean-tests.log, including startup,
dark-host contrast, failed-restore retry, wake/lifecycle gating and small-screen/
keyboard/landscape rendering. The legacy suites separately pass 13 checks.
Initial render-capture runs were stopped after stalling, and
obsolete blur-only assertions were updated and rerun. Native screenshot QA
provides the visual evidence instead.

Closed-app Hello Chotu remains UNIMPLEMENTED. Current standby is limited to the
visible main app. A background feature requires a trained offline Hello Chotu
keyword model, opt-in microphone service with visible Stop notification and
OS-compliant activation. A force-stopped app cannot run its own hotword engine
until user interaction restarts it. No background-listening claim is made.
